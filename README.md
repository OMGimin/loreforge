# 설정공방 · LoreForge

**키워드 몇 개부터 기존 설정집까지, 흩어진 아이디어를 일관된 세계관으로 발전시키는 AI 창작 웹 서비스.**

창작자는 ‘새 이야기 만들기’와 ‘기존 설정 검토’ 중 목적을 고른다. 새 이야기는 키워드·메모·설정집 중 가진 재료로 시작하며, 기존 원고 검토는 원문을 유지한 채 쟁점과 근거·수정 방향을 확인한다. 설정 담당·창작 담당·검토 담당 AI가 초안을 만들고 입력 조건과 내부 일관성을 검토한다. 사용자가 채택한 결과만 다음 확장의 기준으로 사용할 수 있다. 기존 설정집은 필수 입력이 아니다. 본문과 관계 그래프를 함께 보면서 인물·사건·규칙을 탐색하고, 근거와 검토 결과를 확인한다.

## 현재 상태

- 별도 작업 트리에서 목적 탭·검토 전용 흐름과 그래프 표시 범위를 구현했다. 현재 코드의 Python 검사 98개·프런트엔드 검사 7개·타입 검사·빌드가 통과했다. 공개 가상 원고 2건의 실제 API 검토에서 분석+검토 2회, 원문 보존·창작/자동 수정 미호출·실제 MCP 근거 조회·보고서 내보내기를 확인했다. 쟁점→근거 이동→그래프 선택의 브라우저 연결도 확인했다. 상세 결과와 남은 확인은 [구현 결과](docs/RESULTS.md)를 따른다. 기존 main에는 병합·푸시하지 않았다.
- 2026-10-20: 기존 로컬 웹 MVP 구현. 입력·생성·검토·최대 1회 수정·그래프·채택·이어쓰기를 연결했다.
- 공개 키워드 첫 설정, 채택 후 이어쓰기, 짧은 가상 설정집 확장을 실제 OpenAI API로 확인했다.
- 자동·타입·빌드 검사, 모의 브라우저 흐름과 별도 폴더의 잠금 파일 설치를 확인했다. 검토용 새 사례 6건은 v3·v4에서 각각 기대 판단과 일치했다. 이 결과를 일반 정확도나 사람의 창작 품질 평가로 확대하지 않는다.
- 공개 입력의 LangSmith 기록은 원격 API로 분석·생성 root 2개와 총 10개 span을 조회했다. 웹 화면 로그인 후 표시는 미확인이다. 최신 검사 수치와 실행별 한계는 [구현 결과](docs/RESULTS.md)에 기록한다.
- 개인 이해·평가는 개인 확인에 사용할 기존 설정집으로 진행한다. 개인 실행과 비교 자료를 준비했고 작성자로부터 구조 제안이 유용하며 설명문 형태를 유지하겠다는 평가를 받았다. 작성자는 원래 설정 의도가 대체로 유지됐다고 평가했으며 구체적인 선택지는 열린 채로 두기로 했다. 전체 채택과는 구분한다. 특정 작품에 맞춘 기능 변경은 하지 않고 개인 원문·생성물은 Git에서 제외한 `runtime/`에만 보관하며 추적은 끈다.
- API 키는 로컬 `.env`에서만 읽는다. 새 환경에서는 각자의 키 설정이 필요하다.
- 기존 AI 구독을 사용하는 CLI 연결은 후속 확장 후보다. 이번 MVP는 API 방식이다.

## 3일 MVP

두 목적 탭이 원문 등록·분석·저장을 공유한다. 다음은 생성 흐름이며 검토 전용 사용법은 아래에 정리했다.

1. ‘새 이야기 만들기’ 또는 ‘기존 설정 검토’를 선택하고 공통 입력창에 키워드·메모·설정집을 넣는다. `.txt`/`.md` 가져오기와 반드시 지킬 조건은 선택 사항이다.
2. 입력에서 정리한 설정 후보·조건을 확인한다. AI의 추측은 확정 설정으로 저장하지 않는다.
3. 새 입력에 요청이 없으면 첫 설정 초안 하나를 제안한다. 이어쓰기는 다음 사건을 기본 제안하고, 요청이 있으면 그 내용으로 구체화한다.
4. 입력 조건·채택한 설정과의 충돌, 초안 내부 모순, 설명 부족을 근거 위치와 함께 검토한다.
5. 필요할 때 최대 1회 수정하고 재검토한다. 미해결 문제와 판단 불가를 그대로 표시한다.
6. 본문·그래프를 전환하고 노드나 관계를 선택해 상세 내용·근거·관련 검토 결과를 확인한다.
7. 문서 단위로 채택·보류하고 Markdown으로 내보낸다. 채택한 결과는 ‘이 설정 이어쓰기’로 다음 작업의 기준에 포함할 수 있다. 입력 원문과 이전 결과는 보존한다.

## 구성

| 영역 | 선택 |
|---|---|
| 화면 | 데스크톱 브라우저용 Vue 3 웹 화면: 자료 목록·본문/그래프·상세/검토 |
| 그래프 | Cytoscape.js, 읽기·탐색 전용, 본문·항목·관계·근거를 담은 공통 문서에서 표시 |
| 서버 | FastAPI |
| 실행 흐름 | LangGraph, 생성은 역할 3개의 순차 검토·최대 1회 수정, 검토 전용은 분석+원고 검토 1회 |
| 모델 | 설정 담당 `gpt-5.4-mini`, 창작·검토 담당 `gpt-5.4`; 역할별 환경변수 |
| 근거 조회 | 버전·문단 ID가 있는 입력/채택 설정 저장소 + 읽기 전용 MCP 도구 1개 |
| 저장 | SQLite, 입력·기준 설정·초안·검토·채택 상태와 버전별 그래프 데이터 구분 |
| 진행 표시 | 단계별 SSE 이벤트 |
| 평가 | 기능 검증 우선, 같은 초안의 단일 생성과 검토 루프 비교는 보너스 목표 |

브라우저에서 로컬 개발 서버에 접속하는 웹 앱이다. Obsidian 설치나 플러그인은 필요하지 않으며, 외부 배포는 이번 3일 범위에 포함하지 않는다.

## 설치와 실행

Python 3.11, Node.js 22.12 이상이 필요하다. 설치 시 Python 의존성 잠금 파일과 npm lockfile을 사용한다.

```bash
cd /path/to/loreforge
bash scripts/setup.sh
cp .env.example .env
# .env의 OPENAI_API_KEY에 본인의 기존 키를 로컬 편집기로 설정한다.
bash scripts/dev.sh
```

이미 `.env`가 있으면 복사 명령을 건너뛴다. 키를 `.env.example`에 적거나 채팅·커밋에 넣지 않는다. 브라우저에서 **http://127.0.0.1:5173**을 연다. 서버 API 문서는 **http://127.0.0.1:8000/docs**다. 실행 스크립트는 기존 프로세스나 DB를 삭제하지 않으며, 포트 충돌은 안내하고 종료한다.

API 호출 없이 화면과 흐름을 확인하려면 다음 명령을 사용한다. 고정 응답이며 실제 AI 품질 검증이 아니다. 모의 데이터는 `runtime/mock.db`로 분리된다.

```bash
bash scripts/dev.sh --mock
```

환경변수는 `.env.example`에 정리했다. 모델을 바꾸면 해당 실행의 요청 모델·실제 응답 모델·프롬프트 버전이 기록된다. LangSmith 키는 선택 사항이며 화면에서 명시적으로 켠 실행에만 **본문을 제외한 실행 메타데이터**를 보낸다.

## 사용 순서

‘새 이야기 만들기’의 순서는 다음과 같다.

1. 키워드나 메모를 적거나 UTF-8 TXT/MD 파일을 가져온다.
2. ‘재료 정리하기’를 누르고 필요한 조건만 선택한다.
3. ‘첫 설정 만들기’를 누른다. 요청을 비워두어도 된다.
4. 본문/관계를 전환하고 항목·관계·검토 쟁점의 근거를 확인한다.
5. 최종 문서를 채택하거나 보류한다. 채택 후 ‘이 설정 이어쓰기’로 다음 사건을 요청한다.
6. ‘근거와 함께 Markdown 내보내기’로 결과와 판단을 저장한다.

‘기존 설정 검토’에서는 원고를 입력하거나 UTF-8 TXT/MD를 가져온 뒤 재료를 분석하고 필요한 보호 조건만 확인한다. 원고 검토를 실행하면 창작·자동 수정 없이 한 번 검토한다. 쟁점 유형·원문과 관련 조건의 인용·이유·수정 방향을 확인하고 해당 문단으로 이동하거나 Markdown 검토 보고서를 내보낸다. 원문은 보존하며 검토 실행에는 채택·보류·이어쓰기를 제공하지 않는다. 쟁점이 없다는 결과도 원고의 정확성을 보증하지 않는다.

두 탭의 입력·파일 본문은 분석과 실행을 위해 OpenAI API로 전송된다. 로컬 웹 실행과 외부 모델 호출을 구분하고 비공개 원고의 추적은 끈 상태로 사용한다. 입력 원고·보호 조건을 합한 기준 20,000자와 파일 100KB 제한을 적용하며 큰 원고를 자동 요약·검색하지 않는다.

검토 전용은 분석 1회+검토 1회로 정상 2회, 작업 전체의 일시 오류 재시도 1회 포함 최대 3회다. 생성은 재료 정리까지 포함해 최대 5회 모델 호출, 일시 오류 재시도 포함 최대 6회다. 화면 조작·이력 조회·새로고침은 유료 호출을 만들지 않는다. 실패한 실행을 자동 재개하지 않는다. 검토 실패는 통과가 아니며, 미해결 쟁점은 채택 후에도 남는다.

## 검증 명령

```bash
bash scripts/check.sh
# 모의 서버 실행 후 별도 터미널에서 브라우저 검사
npx --prefix frontend playwright install chromium
npm --prefix frontend run browser:check
# 설치된 Chrome을 사용하려면 BROWSER_EXECUTABLE_PATH에 실행 파일 경로를 지정한다.
```

브라우저 검사는 모의 제공자인지 먼저 확인하며 실제 API 서버에는 실행하지 않는다. 캡처와 보고서는 `runtime/browser-verification/`에 저장한다.

다음은 **실제 API 비용이 발생하는** 공개 가상 입력 검증이다. 결과는 매번 별도 `runtime/verification-*/` 폴더와 DB에 저장한다.

```bash
.venv/bin/python scripts/verify_live.py --execute --review-cases
# 변경한 모델 연결만 좁게 다시 확인
.venv/bin/python scripts/verify_live.py --execute --quick
# 개발용 고정 검토 8건만 실행
.venv/bin/python scripts/verify_live.py --execute --cases-only
# 별도로 고정한 검토 사례 6건만 실행
.venv/bin/python scripts/verify_live.py --execute --cases-only --fixture-path fixtures/review_holdout.json
```

`--trace`를 추가하면 공개 입력 워크플로의 외부 메타데이터 추적을 명시적으로 요청한다. 키가 없거나 추적에 실패해도 생성·검토와 별도로 경고한다. 추적 전송 요청과 원격 수신은 구분한다. 저장한 공개 검증 보고서의 원격 수신은 `.venv/bin/python scripts/verify_trace.py runtime/verification-실행폴더/report.json`으로 조회·대조할 수 있다. 웹 화면 로그인 후 표시는 별도 확인 항목이다.

## 원문과 키 관리

원본 설정집·개인 입력은 `local/`, 실행 데이터는 `runtime/`, 내보낸 결과는 `exports/`에 둔다. 이 경로와 `.env`는 Git에서 제외한다. API 키는 서버 환경에서만 읽고 브라우저에 전달하지 않는다.

공개 테스트와 fixtures에는 공개용 키워드와 짧은 가상 설정을 사용해 공통적인 창작 흐름을 검증한다. 별도로 요청한 개인 확인에 사용할 기존 설정집은 개인 이해·평가에만 사용하고 공개 fixtures나 특정 작품용 기능으로 옮기지 않는다. LangSmith는 공개용 가상 입력 1건으로 실행 흐름을 확인하는 우선 검증 항목이다. 추적은 기본 비활성으로 두고 해당 확인 작업에서만 명시적으로 켠다. 현재 추적 구현은 선택 여부와 관계없이 원문·프롬프트·출력 본문을 보내지 않는다.
