# 설정공방 · LoreForge

**키워드로 세계관을 만들고, 기존 원고의 설정 충돌을 근거와 함께 살펴보는 AI 창작 웹 서비스.**

게임·소설·웹툰의 설정이 늘어나면 인물의 행동, 사건 순서, 세계관 규칙을 반복해서 대조해야 한다. LoreForge는 생성과 검토를 목적별로 나누고, 본문·관계 그래프·근거 문단을 연결해 확인할 위치를 찾도록 돕는다. AI의 제안과 창작자가 채택한 설정을 구분하며, 최종 판단은 창작자에게 남긴다.

## 두 가지 사용 흐름

| 목적 | 입력 | 실행과 결과 |
|---|---|---|
| **새 이야기 만들기** | 키워드·메모 또는 기존 설정집 | 설정 분석 → 초안 생성 → 검토 → 필요 시 최대 1회 수정·재검토 → 문서 채택·보류 → 채택 결과에서 이어쓰기 |
| **기존 설정 검토** | 이미 작성한 설정집·스토리 | 설정 분석 → 원고 검토 1회 → 쟁점·관련 문단·이유·수정 선택지 확인. 원문 재작성과 자동 수정은 하지 않음 |

기존 설정집 없이 키워드 몇 개로 시작할 수 있다. 두 흐름 모두 자유 텍스트와 UTF-8 TXT/MD 가져오기를 지원하며, 반드시 유지할 조건은 선택 입력이다. 생성 결과는 근거·검토 결과와 함께, 검토 전용 결과는 검토 보고서로 Markdown 내보내기가 가능하다.

## 주요 기능과 개발 구조

| 구성 | 구현 내용 |
|---|---|
| **역할별 실행** | LangGraph의 설정 분석·창작·검토 노드와 조건부 수정 분기. 목적에 따라 생성과 검토 전용 경로를 분리 |
| **문서와 그래프의 공통 데이터** | Pydantic으로 본문·항목·관계·근거의 구조화 출력을 검증. 문서 버전·문단 ID로 본문, Cytoscape 그래프, Markdown을 연결 |
| **근거 조회** | 읽기 전용 MCP 도구 `get_passages(context_version, passage_ids)`로 기준 문단을 재조회. 존재하지 않는 참조를 거절 |
| **과도한 지적 보완** | 검토 후보를 원문 전체의 설명·예외·회차별 분기와 대조. 이미 설명된 내용과 선택적 상세화는 문제 목록에서 제외하도록 구성 |
| **선택과 저장** | SQLite에 원문·기준 스냅샷·문서 버전·실행·채택 상태 저장. 보류 결과는 다음 기준에서 제외하고 미해결 쟁점은 유지 |
| **실행 제어** | 요청 ID로 중복 실행 방지, 동시 AI 작업 1개, 호출·재시도·수정·시간 상한 적용. 실패·중단·미해결을 정상 완료와 구분 |
| **진행과 추적** | SSE로 진행 상태 전달. 선택한 실행만 LangSmith에 모델·분기·MCP·사용량 메타데이터 전송 |

본문과 관계는 같은 구조화 응답에서 만들어지며 그래프만을 위한 추가 모델 호출은 없다. 현재 RAG는 사용하지 않고, 길이 제한 안의 원문·조건·채택 문서를 기준으로 제공한다. 관계 그래프는 본문 탐색용이며 GraphRAG나 직접 편집 도구가 아니다.

### 화면과 탐색

- **읽기 화면:** 딥 네이비 상단·자료 패널, 밝은 본문, 사파이어 블루 선택 강조. 본문은 데스크톱 18px·좁은 화면 17px, 줄 간격 1.85, 문서 영역 최대 폭 800px로 구성한다.
- **검토 화면:** 쟁점을 먼저 보고 관련 원문으로 이동한다. 유형은 기준 충돌·내부 모순·설명 부족·의도 확인으로 구분한다. 제외 후보의 근거와 이유가 반환된 경우에는 별도로 펼쳐볼 수 있다.
- **관계 그래프:** 인물·세력·장소·사건·규칙을 표시한다. 관계 묶음·선택 중심 배치, 크게 보기, 확대·축소·맞춤, 검색·종류·상태·이웃 필터를 제공한다.
- **문서 구분:** 현재 문서를 기본으로 표시하고 기준 문서는 선택적으로 함께 본다. 이름이 같아도 다른 문서의 항목을 자동 병합하지 않는다. 항목과 관계는 키보드로 탐색할 수 있는 목록도 제공한다.

## 기술 구성

| 영역 | 기술 |
|---|---|
| 프런트엔드 | Vue 3, TypeScript, Vite, Cytoscape.js |
| 백엔드·저장 | Python, FastAPI, Pydantic, SQLite |
| AI 실행 | OpenAI Responses API, LangGraph |
| 기본 모델 | 설정 분석 `gpt-5.4-mini` / 창작·검토 `gpt-5.4` — 역할별 환경변수로 변경 가능 |
| 연동·관측 | MCP stdio, SSE, 선택적 LangSmith 추적 |

실제 요청 모델·응답 모델·프롬프트 버전·토큰·호출 수를 실행별로 기록한다. 기존 AI 구독을 사용하는 CLI 연동은 구현 범위에 포함하지 않으며, 이번 MVP는 OpenAI API 방식이다.

## 설치와 실행

Python 3.11~3.13과 Node.js 22.12 이상이 필요하다. 기본 설치 명령은 `python3.11`을 사용하며, 다른 Python 실행 파일은 `LORE_PYTHON`으로 지정할 수 있다. Python 의존성과 프런트엔드 패키지는 잠금 파일로 설치한다.

```bash
cd /path/to/loreforge
bash scripts/setup.sh
```

### 실제 AI 실행

`.env`가 없는 경우에만 예시 파일을 복사한다. `.env`를 로컬 편집기로 열어 `OPENAI_API_KEY`를 설정한다.

```bash
cp .env.example .env
bash scripts/dev.sh
```

- 웹 화면: **http://127.0.0.1:5173**
- API 문서: **http://127.0.0.1:8000/docs**
- 종료: 실행한 터미널에서 `Ctrl+C`

이미 `.env`가 있으면 복사 명령을 건너뛴다. 키는 `.env.example`이나 커밋에 넣지 않는다. 실행 스크립트는 포트 충돌 시 안내하고 종료하며, 기존 서버를 강제 종료하거나 DB를 삭제하지 않는다. 별도 작업 트리의 시연 포트와 위 기본 실행 포트는 다를 수 있다.

### API 호출 없는 모의 시연

```bash
bash scripts/dev.sh --mock
```

고정 응답으로 화면과 실행 흐름을 확인한다. 실제 AI 품질 검증이 아니며 모의 DB는 `runtime/mock.db`로 분리된다. 실제 실행과 모의 실행은 같은 기본 포트를 사용하므로 동시에 시작하지 않는다.

## 사용 방법

### 새 이야기 만들기

1. 목적 탭에서 **새 이야기 만들기**를 선택하고 키워드·메모·파일을 입력한다.
2. **재료 정리하기**를 누르고 유지할 조건을 확인한다.
3. **첫 설정 만들기**를 실행한다. 요청을 비워두어도 시작할 수 있다.
4. 본문과 관계도를 살펴보고 검토 쟁점의 근거 문단을 확인한다.
5. 최종 문서를 채택하거나 보류한다. 채택하면 **이 설정 이어쓰기**로 확장할 수 있다.
6. **근거와 함께 Markdown 내보내기**로 결과를 저장한다.

### 기존 설정 검토

1. 목적 탭에서 **기존 설정 검토**를 선택하고 원고를 입력한다.
2. 재료를 정리하고 필요한 조건과 중점 검토 요청을 확인한다.
3. 원고 검토를 실행한 뒤 문제 위치·관련 설정·이유·수정 선택지를 살펴본다.
4. 근거 버튼으로 해당 문단에 이동하거나 관계도에서 관련 항목을 탐색한다.
5. 검토 보고서를 Markdown으로 내보낸다.

검토 전용 흐름에는 채택·보류·이어쓰기가 없다. 원문은 그대로 보존된다. 어느 흐름에서도 쟁점이 없다는 결과가 원고의 정확성을 보증하지 않는다.

## 실행 한도와 데이터 처리

| 항목 | 제한·동작 |
|---|---|
| 생성 | 준비 분석 포함 정상 최대 5회 호출, 작업 전체의 일시 오류 재시도 1회 포함 최대 6회. 수정은 최대 1회 |
| 검토 전용 | 분석 1회 + 검토 1회, 작업 전체의 일시 오류 재시도 1회 포함 최대 3회 |
| 입력 | 기준 문서·조건·이월 쟁점 등 누적 기준 20,000자, 요청 2,000자, TXT/MD 파일 100KB |
| 그래프 표시 | 최대 30항목·60관계. 한도 초과를 안내하고 검색·필터로 범위를 좁힘 |
| 시간 | 모델 호출별 120초, 자동 실행 구간 전체 10분 |
| 복원 | 새로고침·SSE 재연결·그래프 탐색은 모델을 다시 호출하지 않음. 서버 재시작 당시 실행 중이던 작업은 중단 상태로 남기고 자동 재개하지 않음 |

로컬에서 실행하더라도 분석·생성·검토에 필요한 본문과 조건은 OpenAI API로 전송된다. API 키는 백엔드에서만 읽고 브라우저에 전달하지 않는다.

LangSmith 추적은 기본 비활성이며 실행별로 선택한다. 원문·프롬프트·출력 본문은 보내지 않고 실행 메타데이터만 전송한다. 추적 실패는 핵심 생성·검토 흐름과 분리해 표시한다. 비공개 원고의 추적은 끈 상태로 사용한다.

`.env`, 원본 자료용 `local/`, 실행 데이터용 `runtime/`, 내보내기용 `exports/`는 Git에서 제외한다. 공개 fixtures는 가상 입력으로 구성하고 개인 원문·실행 결과·DB는 포함하지 않는다.

## 검증 현황

아래는 **2026-10-20에 기록한 검증 결과**다. 2026-10-21 README 정리 작업에서는 명령·경로·문서 링크와 공개 버전을 대조했으며 실제 AI 평가를 새로 실행하지 않았다.

| 검증 | 확인한 결과와 범위 |
|---|---|
| 자동 검사 | 검토·관계도 보완 시 Python **105개**, 프런트엔드 **11개**, 타입 검사·빌드 통과 |
| 최신 화면 | 블루 테마 적용 후 프런트엔드 **11개**, 타입 검사·빌드 통과. 1000px 화면의 본문·검토·확대 그래프와 근거 문단 이동 확인 |
| 실제 OpenAI | 공개 입력의 첫 생성·채택 후 이어쓰기·설정집 확장, 검토 전용 분석+검토 흐름 확인 |
| 과잉 지적 회귀 검사 | v7 공개 사례 6건이 기대 결과와 일치. 정상·예외 4건과 설명 부족·내부 모순 각 1건이며 일반 정확도 평가가 아님 |
| LangSmith | 공개 실행의 root 2개·총 10개 span을 원격 API로 조회해 역할·모델·분기·MCP·사용량 대조 |
| 사용자 평가 | 특정 제안의 구조적 유용성과 의도 유지에 대한 작성자 평가 확인. 전체 창작 품질·모든 검토 지적의 타당성 확인과 구분 |

실행별 조건·토큰·시간과 한계는 [구현 결과](docs/RESULTS.md), 최신 화면 검증은 [구현 기록](docs/IMPLEMENTATION.md), 사람의 평가는 [직접 평가](docs/USER_ACCEPTANCE.md)에 기록한다.

### 검사 재현

```bash
# 자동 검사·타입 검사·빌드 (실제 AI 호출 없음)
bash scripts/check.sh

# 모의 서버를 실행한 상태에서 별도 터미널로 브라우저 검사
npx --prefix frontend playwright install chromium
npm --prefix frontend run browser:check
```

브라우저 검사는 서버가 모의 제공자인지 먼저 확인하고 실제 API 서버에서는 중단한다. 설치된 Chrome을 사용하려면 `BROWSER_EXECUTABLE_PATH`를 지정한다. 결과는 `runtime/browser-verification/`에 저장한다.

다음 명령은 **실제 API 비용이 발생하는** 공개 입력 평가다. 실행 목적에 맞는 명령 하나를 선택한다.

```bash
# 생성·이어쓰기·설정집 확장 및 개발용 검토 사례
.venv/bin/python scripts/verify_live.py --execute --review-cases
# 키워드 생성 흐름만 확인
.venv/bin/python scripts/verify_live.py --execute --quick
# 별도로 고정한 검토 사례 6건
.venv/bin/python scripts/verify_live.py --execute --cases-only --fixture-path fixtures/review_holdout.json
# 과잉 지적 방지용 공개 원고 6건
.venv/bin/python scripts/verify_review_screening.py --execute
```

`verify_live.py`는 `runtime/verification-*/`, `verify_review_screening.py`는 `runtime/screening-*/report.json`에 결과를 저장한다. 후자는 검토 6회와 건별 일시 오류 재시도 최대 1회를 허용하며 `--execute` 없이 실행하면 API를 호출하지 않는다.

`verify_live.py`에 `--trace`를 추가하면 공개 입력 워크플로의 추적을 요청한다. 전송 요청과 원격 수신은 구분하며, 저장한 보고서는 다음 명령으로 원격 기록과 대조한다.

```bash
.venv/bin/python scripts/verify_trace.py runtime/verification-실행폴더/report.json
```
