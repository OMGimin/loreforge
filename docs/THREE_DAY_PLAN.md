# LoreForge 3일 구현 계획

기간: **2026-10-20(화)~2026-10-22(목), Asia/Seoul**

기획·저장소 연결과 로컬 MVP 구현을 마쳤다. 아래는 3일 일정의 기준이며 실제 검사 결과는 [구현 결과](RESULTS.md)에서 구분한다. 3일 동안 데스크톱 브라우저용 웹 앱으로 키워드 시작·기존 설정 활용·본문과 그래프 탐색을 구현한다. 로컬 개발 서버에서 실행하며 외부 배포는 별도 범위다. 직접 발표하지 않을 가능성을 반영해 발표자료 제작과 5분 리허설은 현재 필수 완료조건에서 제외한다. 결과보고·실행·검증 문서는 유지하며, 공식 발표 면제 여부를 확인한 것은 아니다.

## 1. 이번 과제의 제출 방향

과제 유형은 **신규 프로젝트 개발**로 정했다. 수업 Base의 FastAPI·LangGraph·MCP·Vue 구조를 참고하되, 주제와 사용자 흐름은 세계관 만들기·확장·검토·관계 탐색으로 구성한다.

2026-10-20 오전 전사록 후반의 정정 안내를 일정에 반영했다. 현재 로컬 PDF의 14시 마감은 이전 안내다. **13시를 준비 기준으로 적용하되, 수정 PDF와 발표 세부 시각은 추가 확인이 필요하다.** 전사에는 인식 오류와 주변 대화가 섞여 있어 후반의 반복 안내를 우선 해석했다. 자료별 근거는 [참고 자료](REFERENCES.md)에 정리했다.

| 시점 | 제출·완료 기준 | 근거·확인 상태 |
|---|---|---|
| 10/20 17:00까지 | 선택 과제와 진행 계획 초안 등록. 정해지는 대로 먼저 등록하고 개발 가능 | 초기 PDF 및 오전 안내. 조기 등록 허용을 마감 폐지로 해석하지 않음 |
| **10/22 13:00까지** | **구현·결과보고 마무리, 공개 Git·보고서 주소 제출 준비** | 오전 전사 후반 정정 안내에 따른 준비 기준. 수정 PDF 대조 필요 |
| 기존 발표 안내 | 개인별 Zoom 5분과 직접 반영한 코드 설명 | 당시 수업 안내로 보존. 현재 발표자료·리허설은 필수 작업에서 제외 |

기존 PDF의 17:30 발표 종료 표기는 수정본 확인 전에는 확정 시각으로 쓰지 않는다. 코드 저장소와 결과보고는 평가자가 공개 접근할 수 있어야 하며 GitHub Markdown 보고서도 가능하다. 공개용 가상 입력으로 재현 방법을 제공하고, 결과보고서·실행 방법·검증 결과·설계 이유를 정리한다. 기존 발표 원고는 선택 참고자료로 보존한다.

제출 전에는 공개할 파일과 자료를 직접 점검한다. 업로드 후에는 저장소와 보고서 링크가 실제로 열리는지, 제출이 정상 처리됐는지 확인한다.

### 과제 등록용 요약

> 설정공방 LoreForge는 키워드 몇 개부터 기존 설정집까지, 흩어진 아이디어를 일관된 세계관으로 발전시키는 AI 창작 웹 서비스입니다. 설정 담당·창작 담당·검토 담당의 생성→검토→최대 1회 수정 흐름을 구현합니다. 처음에는 입력 조건과 초안 내부 모순을 검토하고, 사용자가 채택한 설정은 다음 확장의 기준으로 활용합니다. 공개 키워드와 가상 설정으로 첫 설정 생성, 채택 후 이어쓰기, 기존 설정 확장을 검증합니다. 본문·항목·관계·근거를 공통 구조로 저장해 본문과 그래프에서 탐색할 수 있게 합니다. OpenAI API와 FastAPI·LangGraph·SQLite·Vue·Cytoscape.js를 사용하고, 읽기 전용 MCP로 기준 문단을 조회합니다. 핵심 기능을 먼저 완성하고, 공개 입력의 실행 추적과 가능한 범위의 동일 초안 전후 비교로 구현·효과·한계를 설명합니다.

## 2. 구현 순서와 범위

문서·그래프 데이터 계약 → 재료 입력 → 첫 설정·그래프 표시 → 검토·수정 → 근거·쟁점 연결 → 채택·이어쓰기 → 웹 검증·결과 정리.

[기획서](PROJECT_PLAN.md)의 **F1~F7과 F9가 필수**다. F8은 기능 안정화 후 수행하는 비교 평가 보너스 목표다. LangSmith 공개 입력 1건의 추적은 우선 검증 항목이다. 모든 기술 목록을 필수로 구현하거나 여러 시작 모드를 따로 만들지 않는다.

## 3. Day 1 — 키워드에서 첫 설정까지

목표: 키워드만으로 실제 OpenAI 응답을 받고, 본문과 기본 관계 그래프를 웹에서 확인한다. 문서 형식은 [설정 문서 구조](SETTING_DOCUMENT_FORMAT.md)를 따른다.

| 순서 | 작업 | 산출물 | 확인할 증거 |
|---|---|---|---|
| 1 | Base 구조 파악·로컬 환경 준비 | 설치·실행 안내, `.env.example`, 차용할 구조 메모 | 내가 바꿀 역할과 흐름 설명, 키가 화면·로그에 노출되지 않음 |
| 2 | 모델·구조화 출력 확인 | 모델 ID·usage·지연 기록 | 공개 키워드 입력으로 실제 응답 수집 |
| 3 | 본문·항목·관계·근거와 기존 상태 계약 | StoryDocument 포함 모델·SQLite 모듈, 공개 예제 | 문서 버전·항목 ID·근거·관계 끝점 검증 |
| 4 | 재료 입력과 후보·선택 조건 | F1·F2, 텍스트 입력창과 선택적 TXT·MD | 짧은 키워드와 기존 본문 모두 수용, 없는 근거를 만들지 않음 |
| 5 | 첫 설정 또는 확장과 관계 데이터 생성 | F3·F9 데이터, 초안 저장 | 기존 응답에 본문·항목·관계 포함, 추가 모델 호출 없음 |
| 6 | Vue 웹 화면·Cytoscape.js 기본 연결 | F9 기본 표시, 본문/그래프 전환·확대/축소·선택 | 공개 예제와 실제 생성 결과에서 노드·관계 선택 시 본문 위치 표시 |

17:00 이전에 계획 초안을 등록할 수 있도록 기획서부터 준비한다. 등록 준비와 개발을 병행한다.

**Day 1 통과 기준**

- [ ] 공개 키워드 3개만으로 설정집·추가 요청 없이 첫 초안을 생성한다.
- [ ] 메모·본문 입력도 같은 화면과 파이프라인으로 처리한다.
- [ ] 본문·항목·관계·근거 형식으로 저장하고 노드/관계 선택에서 실제 문단으로 이동한다.
- [ ] 기본 그래프와 목록을 렌더링하고 빈 관계·잘못된 끝점·그래프 부분 실패를 표시한다.
- [ ] 반드시 지킬 조건은 선택 사항이며, 지정한 경우 실제 실행 입력에 남는다.
- [ ] AI의 추론·새 설정이 자동으로 채택된 기준에 들어가지 않는다.
- [ ] 키·모델·구조화 출력·usage를 실제 환경에서 확인하고 설치·재실행 방법을 기록한다.

**막히면:** 모델 비교·별도 입력 모드·여러 대안 동시 생성을 추가하지 않는다. 모의 응답으로 UI를 개발할 수 있지만 실제 API 검증 전에는 연결 완료로 표시하지 않는다.

## 4. Day 2 — 검토·수정·채택·이어쓰기

목표: 검토 결과를 그래프·본문에 연결하고, 채택한 결과로 이어쓸 때 문서 상태와 관계가 함께 유지되도록 한다.

| 순서 | 작업 | 산출물 | 확인할 증거 |
|---|---|---|---|
| 1 | 검토 역할과 근거 계약 | F4 | 기준 충돌은 기준+초안 위치, 내부 모순은 초안 두 위치, 근거 부족은 판단 불가 |
| 2 | 기준 문단 MCP 조회 | 읽기 전용 도구 1개 | 실제 stdio 호출로 입력·조건·채택 문단 확인, 잘못된 버전·ID 거절 |
| 3 | LangGraph 검토→수정→재검토 | F5 | 수정 최대 1회, 미해결은 `needs_attention` |
| 4 | SSE·실패 처리·본문/그래프·상세 패널 | F7·F9 | 버전 전환·종류 필터·이웃 강조, 검토 쟁점→노드/관계→근거 이동 |
| 5 | 채택·보류·이어쓰기·문서 틀에 맞춘 내보내기 | F6·F9 | 상태 라벨 갱신, 채택한 최종 문서만 새 기준에 포함, Markdown 본문·관계·근거 일치 |
| 6 | 이력·재시작 복원 | F7·F9 | 문서·관계·채택 상태 복원, 좌표는 재배치 가능, 중단 작업의 자동 유료 재실행 없음 |
| 7 | 공개 입력 LangSmith 추적과 가상 설정 검증 | 실행 흐름 기록, 가상 설정의 검토 결과 | 공개 입력만 추적하고 비공개 자료 추적은 꺼짐, 채택 이유 기록 |
| 8 | 설계 이유와 코드 위치 정리 | 구현 문서·결과보고 | 내가 수정한 핵심 코드와 Base 차용 부분 구분 |

**Day 2 통과 기준**

- [ ] 키워드→생성→검토→채택→이어쓰기 1회가 동작한다.
- [ ] 기존 설정집에서도 보호 조건·근거를 확인하며 같은 흐름이 동작한다.
- [ ] 그래프의 입력·제안·채택 상태를 라벨로 구분하고, 노드/관계와 검토 쟁점의 근거가 일치한다.
- [ ] 키보드로 목록을 선택해 같은 상세를 볼 수 있고 좁은 화면에서도 본문을 읽을 수 있다.
- [ ] 새 버전에 이전 버전의 관계·검토 쟁점이 섞이지 않고, 동일 이름의 항목을 자동 병합하지 않는다.
- [ ] 첫 생성에 기존 기준이 부족하다는 사실을 숨기거나 원문 인용을 만들어내지 않는다.
- [ ] 실제 지적이 없으면 억지 수정이나 오류 연출을 하지 않는다.
- [ ] 보류 결과·수정 전 초안이 다음 기준에 자동 편입되지 않는다.
- [ ] 검토 실패·한도 도달을 통과로 바꾸지 않고 미해결 쟁점을 채택 후에도 보존한다.
- [ ] 재시작 후 입력·기준·결과·선택을 복원하고 기존 DB나 다른 프로세스를 삭제하지 않는다.
- [ ] LangSmith 추적의 수행 여부·남은 설정 문제를 기록한다. 추적이 없어도 로컬 실행 상태는 확인 가능하다.

**막히면:** 토큰 단위 스트리밍·화려한 차이 강조·그래프 애니메이션을 제외한다. 그래프는 기본 배치 하나와 필수 탐색만 유지한다. 직접 노드/연결선 편집은 추가하지 않는다. MCP가 지연되면 직접 저장소 호출로 전체 흐름을 먼저 검증하되 MCP 미구현 사실을 명시한다. 추적 설정 문제 때문에 핵심 생성·검토를 멈추지 않는다.

## 5. Day 3 — 13시까지 구현·결과보고 완료

목표: **13:00까지 구현·결과보고를 마무리**한다. 현재는 발표자료·5분 리허설 대신 실행·검증 문서와 개인 이해·평가를 정리한다. 평가 방법은 [평가 계획](EVALUATION.md)을 따른다.

| 시간대 | 작업 | 산출물 |
|---|---|---|
| 오전~10:30 | 핵심 기능·문서/그래프 일치·웹 실패 경로 검사와 수정 | 실행 가능한 코드, 검사 결과, 미완료 항목 |
| 10:30~11:15 | 기능 안정 시 동일 초안 전후 비교 | 공개 입력의 비교 기록, 사람 판단·시간·토큰. 불가 시 미수행 명시 |
| 11:15~12:00 | 검증 결과·한계·코드 설명 정리 | 키워드 시작·그래프 탐색 결과, 채택 이유, 핵심 코드 위치 |
| 12:00~12:40 | README·결과보고·실행 안내 마무리 | 공개 재현 방법, 검사 결과, 설계·한계 문서 |
| 12:40~13:00 | 제출 항목과 공개 범위 확인 | Git·보고서 주소, 비공개 자료 제외, 실제 제출 상태 |

12:00 이후에는 새 기능을 추가하지 않고 필수 수정과 결과 정리만 한다. 개인 원고 확인은 공통 기능을 이해·평가하는 작업으로 분리한다. 13:00 뒤의 제출물 수정은 별도 안내를 확인한다.

**Day 3 통과 기준**

- [ ] F1~F7·F9의 완료·미완료와 F8 보너스 수행 여부를 구분한다.
- [ ] 공개 키워드와 가상 설정만으로 핵심 흐름을 재현할 수 있다.
- [ ] 30노드·60관계 예제로 확대·이동·필터·선택이 가능하고, 표시 한도 초과·잘못된 관계·빈 그래프를 안내한다.
- [ ] 새로고침 후 본문·관계·채택 상태를 복원하고 그래프 조회·조작이 모델 호출을 늘리지 않는다.
- [ ] 실측 비교를 했다면 동일한 기준·초안의 결과, 호출 수·시간·토큰과 악화된 항목도 제시한다.
- [ ] 모델이 생성한 결과와 의도적으로 오류를 넣은 시험용 초안을 구분한다.
- [ ] 실행 문서와 결과보고에서 목적·내가 수정한 코드·검증·한계를 설명한다. 발표자료 제작과 5분 리허설은 현재 필수 조건에서 제외한다.
- [ ] 원문·키·비공개 로그가 공개 파일에 섞이지 않았는지 확인한다.
- [ ] 공개할 내용을 점검한 뒤 푸시·제출하고, 원격 내용·공개 접근·제출 상태까지 확인한다.

## 6. 일정이 부족할 때의 축소 순서

1. 꾸미기·문단별 diff·결과 집계 UI·그래프 애니메이션을 제외한다. 기본 배치는 하나로 고정한다.
2. 추출 종류 자동 분류를 줄이고 재료·조건·근거 확인에 집중한다.
3. 역할별 모델 배정과 초안 하나를 유지한다. 추가 모델 비교·다중 대안·긴 질문 인터뷰·개별 설정 편집기는 추가하지 않는다.
4. 보너스 평가는 공개 입력 A/B 1쌍부터 시작하고 여유가 있을 때 늘린다. 핵심 기능이 미완성이라면 비교를 미수행으로 남긴다.

**줄이지 않을 것:** 키워드만으로 시작, 입력·제안·채택의 분리, 채택 후 이어쓰기, 원문 보존, 실제 생성·검토, 유효한 근거, 수정 상한, 미해결 표시, 기본 실패 처리, 본문·그래프 전환, 노드/관계 선택과 근거 연결, 상태 구분.
