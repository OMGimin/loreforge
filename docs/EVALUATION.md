# 평가 및 시연 계획

상태: 평가 설계, **실측 결과 없음**. 필수 F1~F7의 작동을 먼저 확인한다. 같은 초안 전후 비교(F8)는 과제 +10점 보너스 목표로, 기능 안정화 뒤에 검토 루프의 효과와 추가 비용을 함께 확인한다.

## 1. 무엇을 비교할 것인가

| 조건 | A: 단일 생성 | B: 검토 루프 |
|---|---|---|
| 입력·채택 설정의 기준 스냅샷·실제 요청·보호 조건 | 동일 | 동일 |
| 모델·생성 프롬프트·출력 제한 | 동일 | 동일 |
| 설정 추출 결과 | 동일한 확인된 후보·조건 재사용 | 동일한 확인된 후보·조건 재사용 |
| 초안 | 생성한 초안 D0 | **같은 D0**에서 출발 |
| 후속 처리 | 없음 | 검토, 필요 시 수정 1회+재검토 |
| 최종 결과 | D0 | 수정본 또는 수정 불필요한 D0 |

첫 비교는 같은 초안을 공유하므로 생성 운에 따른 차이를 줄인다. 전체 시스템 비교가 필요하면 동일한 입력으로 따로 실행한 결과도 추가할 수 있지만, 공유 초안 비교와 별도 실행 비교를 섞지 않는다.

설정 추출은 공통 준비 비용으로 별도 기록한다. A 비용은 초안 생성, B 비용은 초안 생성+검토+실제로 수행한 수정·재검토를 포함한다. B의 검토 시간만 A 전체 시간과 비교하지 않는다.

## 2. 보너스 평가 묶음과 기능 시험

### 실제 확장 품질

- 최소 목표는 공개 입력 **A/B 1쌍**이다. 시간이 허락하면 키워드 첫 설정, 채택 후 확장, 기존 가상 설정집 확장의 3개 조건에 각각 1쌍을 구성한다. 여러 조건을 비교할 때도 각 쌍 안의 기준과 초안 D0는 동일해야 한다.
- 인물의 정보 시점, 세력별 참가 조건, 능력의 제약처럼 구별 가능한 조건을 포함한다.
- 가능하면 강호행의 대표 분기 1쌍을 추가한다. 원문과 생성 결과는 로컬에서만 보관하고 발표에 사용할 범위는 창작자가 결정한다.
- 여유가 있으면 요청별 3회로 늘려 변동을 확인한다. 1회 결과를 통계적 일반화나 높은 정확도 보장의 근거로 쓰지 않는다.

### 필수 기능의 검토 시험

짧은 입력과 고정된 초안 8개를 별도로 만든다. 이는 **의도적으로 구성한 테스트**이며 실제 강호행의 오류라고 소개하지 않는다.

| ID | 케이스 | 기대 동작 |
|---|---|---|
| C1 | 명시적 가족관계와 충돌하는 인물 추가 | 원문과 초안의 대응 구간을 근거로 충돌 후보 표시 |
| C2 | 능력 사용 조건을 설명 없이 위반 | 조건과 장면을 연결해 충돌 후보 표시 |
| C3 | 인물이 정보를 얻기 전에 그 정보를 활용 | 지식 획득 시점과 행동 시점을 검토 |
| C4 | 모순은 없지만 사건의 연결 설명이 빠짐 | 확정 오류가 아닌 설명 부족 표시 |
| C5 | 규칙의 예외가 원문에 명시되어 있음 | 일반 규칙만 보고 잘못 반려하지 않음 |
| C6 | 원문과 일치하는 정상 초안 | 오류를 억지로 만들지 않음 |
| C7 | 키워드만 있는 입력에서 초안 내 능력 규칙 두 개가 충돌 | 초안의 두 위치를 근거로 내부 모순 표시, 없는 기존 설정 인용 금지 |
| C8 | 키워드에 없는 가족관계를 AI가 제안하고 판단 근거도 없음 | 제안으로 유지, 기존 사실로 승격하거나 근거 없이 원작 충돌 판정하지 않음 |

## 3. 평가 지표

| 지표 | 계산·판단 방법 | 주의점 |
|---|---|---|
| 보호 조건 준수율 | 사람이 확인한 준수 조건 수 / 적용 가능한 조건 수 | 조건의 적용 경로·시점을 먼저 고정. 해당 없음은 제외, 적용 조건 0개면 N/A |
| 지적 정밀도 | 사람이 타당하다고 확인한 지적 / 판정 가능한 전체 지적 | 지적 0건이면 N/A. 확인 불가는 별도로 집계 |
| 오류 탐지율 | 찾은 삽입 오류 수 / 의도적으로 삽입한 전체 오류 수 | 정답이 있는 C1~C3 등에만 사용. 실제 원고 전체의 재현율로 확대하지 않음 |
| 오탐 수 | 정상·예외 허용 내용을 충돌이라고 지적한 수 | C5·C6과 실제 결과 모두 기록 |
| 근거 유효율 | 존재하는 문단 ID와 실제 인용이 일치하는 지적 / 근거를 요구하는 지적 | 문단 존재와 인용 일치는 코드 검사, 주장을 뒷받침하는지는 사람 판단 |
| 설명의 충분성 | 0: 연결 없음, 1: 일부 연결, 2: 행동·사건의 이유를 설명 | 창작자가 A/B 결과를 같은 기준으로 판단하고 이유를 남김 |
| 창작 의도 유지 | 0: 핵심 변경, 1: 일부 어긋남, 2: 유지 | 선호와 논리 오류를 구분 |
| 채택 여부·이유 | 결과별 채택 또는 보류, 변경을 원하는 이유 | 단순 길이·문체 취향을 설정 정확도로 계산하지 않음 |
| 지연·호출·토큰 | 실제 경과 시간, 모든 호출 시도, 입력·출력 토큰 | 실패·재시도도 남김. 가상 단가를 실제 비용으로 표시하지 않음 |

실제 이야기 검토의 정답은 자동으로 확정하기 어렵다. 먼저 사람의 판단 기준을 고정하고, AI 자기평가 점수만으로 성능 향상을 주장하지 않는다. 결과를 평가할 때 가능하면 A/B 표기를 가리고 읽는다.

## 4. 기능·상태 검증

핵심 동작을 검증하는 자동 테스트와 실제 환경 확인을 분리한다.

- 입력 검증: 새 작업의 빈 재료는 안내하되 키워드만 있는 입력은 허용. 요청 공란에는 새 입력의 첫 설정 또는 이어쓰기의 다음 사건에 맞는 기본 요청을 기록해 사용. 누적 기준 제한 초과·잘못된 인코딩·지원하지 않는 확장자 처리.
- 시작 흐름: 키워드 3개만으로 첫 설정 생성, 메모·본문도 같은 화면에서 처리, 선택 조건 없이 진행 가능.
- 기준 검증: AI 추론·미채택 초안을 기준으로 자동 편입하지 않음. 채택 결과만 이어쓰기 가능하고 보류 결과 ID를 직접 요청해도 서버에서 거절. 수정본 채택 시 수정 전 초안 제외.
- 검토 기준: 기존 기준과의 충돌은 기준+초안 근거, 내부 모순은 초안 내 두 위치 검증. 기준이 부족한 내용은 판단 불가로 남김.
- 근거 검증: 존재하지 않는 문단 ID, 인용 불일치, 다른 기준 버전의 근거 사용.
- 상태 검증: 수정 최대 1회, 전체 모델 호출 시도 최대 6회, 한도 후 `needs_attention`.
- 실패 검증: 키 없음·401·429·5xx·타임아웃·불완전 출력·거절·파싱 실패. 성공으로 바뀌지 않는지 확인.
- 자료 경계: 문서 내부의 지시를 실행하지 않음, 모델 출력 HTML을 실행하지 않음.
- 보존 검증: 실행 전후 원문 hash 동일, 초안과 수정본 별도 저장, 채택이 원문을 바꾸지 않음. 이어쓰기는 새 기준 버전으로 시작하며 이전 실행의 기준과 미해결 쟁점 보존.
- 복원 검증: 서버 재시작 후 완료된 결과·선택 복원, 진행 중이던 작업은 `interrupted`.
- UI 검증: SSE 재연결로 중복 유료 실행이 생기지 않음, 근거 클릭·결과 탭·내보내기 실제 사용.
- 모델 검증: 공개 키워드의 실제 OpenAI 응답으로 생성·검토·채택·이어쓰기 1회와 공개 설정집 입력 흐름 확인. 모의 테스트만으로 연결 성공을 주장하지 않음.
- 우선 추적 검증: 공개 가상 입력 1건의 LangSmith 실행 흐름 확인. 실제 키·연결과 trace 존재를 확인한 경우에만 완료 표시. 비공개 입력은 추적하지 않으며 추적 실패와 제품 기능 실패를 구분.

추가 서버를 띄우지 않아도 되는 로직은 가짜 모델·저장소로 검사한다. 실제 API 검사는 별도 표시하고 모델명·날짜·호출량을 남긴다.

## 5. 결과 기록

실행별로 입력 hash, 기준 스냅샷 버전·이어받은 채택 결과 ID, 실제 요청, 보호 조건, 모델 ID, 프롬프트 버전, 초안·수정본, 검토 결과, 상태, 시간·usage를 `runtime/`에 보관한다. 사람이 매긴 점수와 채택 이유도 연결한다.

실패와 낮은 점수를 삭제하지 않는다. 공개 결과표에는 비공개 본문을 제외하고 필요한 수치·검증 한계를 요약한다. 아직 없는 결과를 임의 숫자나 예시 수치로 채우지 않는다.

## 6. 개인별 Zoom 5분 발표

오전 전사 후반의 개인 5분·직접 반영한 코드 설명 안내를 적용한다. 시연은 전체 발표 중 **60~90초**다. 아래는 90초 시연을 포함해 총 300초로 구성한 계획이며, 실제 리허설로 확인한다.

| 구간 | 내용 | 보여줄 근거 |
|---|---|---|
| 0:00~0:40 | 문제와 목표 | 키워드부터 시작할 수 있는 이유, 유명 작품 사례는 한 문장으로 제한 |
| 0:40~2:10 | 90초 시연 | 키워드→첫 설정→검토→채택→이어쓰기, 기존 설정 활용은 강호행 결과 1개로 짧게 보충 |
| 2:10~3:30 | 본인이 반영한 코드와 이유 | 기준·제안 분리, 근거 검증, 수정 상한과 종료 상태 중 핵심 코드 |
| 3:30~4:20 | 검증·효과 | 실제 기능 검사, 공개 입력 추적, 수행한 경우에만 동일 초안 비교 수치 |
| 4:20~5:00 | 한계·개선 방향 | 근거 부족, 오탐, 동일 모델의 오류 공유, 추가 지연·토큰 |

자료는 4~5장과 필요한 코드 화면으로 구성한다. 강호행 전문이나 비공개 추적 화면을 공개하지 않는다. 준비물은 13시 전에 완료하고 발표 세부 순서는 수정 안내를 확인한다.

### 시연과 코드 설명 준비

- 키워드 입력에서 출발해 AI 제안과 채택한 설정이 어떻게 구분되는지 보여준다. 긴 생성을 기다리기 어렵다면 실제 저장된 실행 결과를 활용하고 재생임을 표시한다.
- 실제 검토 지적 1개를 기준 또는 초안 위치에 연결한다. 지적이 없으면 오류를 연출하지 않는다.
- 최종 결과를 채택하고 다음 확장 요청의 기준에 포함되는 모습을 보여준다. 미해결 문제는 채택 후에도 남는다.
- 본인이 변경한 코드 위치와 Base에서 참고한 부분을 따로 표시한다. “AI가 작성했기 때문” 대신 조건·근거·종료 로직의 선택 이유를 설명한다.
- 발표 전 타이머로 5분을 확인하고 캡처·저장된 결과를 대체 시연 자료로 준비한다. 보너스 비교를 못 했다면 성능 향상을 주장하지 않는다.

유명 작품은 문제 사례, 공개 키워드·가상 설정은 재현 가능한 시험, 강호행은 기존 설정집의 실제 적용 사례로 구분한다.
