# LoreForge 구현 결과

작성일: 2026-10-20

## 현재 상태

로컬 웹 MVP를 구현하고 공개 가상 입력으로 실제 OpenAI API 흐름을 확인했다. 키워드→생성·검토→최대 1회 수정→그래프→채택→이어쓰기, 기존 설정 입력, Markdown 내보내기, 이력 복원을 제공한다. LangSmith 외부 수신은 키 미설정으로 확인하지 못했다.

화면은 Vue 3·TypeScript·Vite·Cytoscape.js, 서버는 Python 3.11·FastAPI·Pydantic·SQLite·LangGraph로 구성했다. 설정 담당은 `gpt-5.4-mini`, 창작·검토 담당은 `gpt-5.4`를 사용한다. 실제 응답 모델·프롬프트 버전·토큰·호출 수를 기록한다.

## 실제 OpenAI 실행

2026-10-20 공개 키워드와 가상 설정만 사용했다. 금액은 실제 청구액으로 환산하지 않았으며 토큰은 응답 usage의 관측값이다.

| 입력 | 종료 상태 | 호출 수 | 입력 토큰 | 출력 토큰 | 기록 시간(초) |
|---|---|---:|---:|---:|---:|
| 키워드 첫 설정 | completed | 5 | 14,166 | 6,354 | 57.387 |
| 채택 후 이어쓰기 | completed | 5 | 27,523 | 8,404 | 64.878 |
| 가상 설정집 확장 | completed | 5 | 12,741 | 5,776 | 49.072 |
| 참조 목록·응답 처리 보완 후 첫 설정 재검증 | completed | 5 | 13,309 | 6,155 | 57.478 |

앞의 3건은 초기 연결 구현, 마지막 1건은 `loreforge-v2-reference-index`와 Responses.create 기반 구조화 출력 구현의 검사다. 마지막 검토 프롬프트 변경인 `loreforge-v3-review-boundaries`는 아래 고정 검토 8건으로 영향 범위를 재검증했다. 서로 다른 상태의 실행을 동일 버전 반복 측정으로 합치지 않는다.

로컬 증거:

- `runtime/verification-20261020T024107Z/report.json`: 초기 3개 흐름·초안·수정본·검토·usage. 첫 고정 사례에서 잘못된 참조가 반환돼 추가 평가가 중단된 이력도 있었다. 잘못된 참조는 서버에서 거절했으며 성공으로 바꾸지 않았다.
- `runtime/verification-20261020T024752Z/report.json`: 보완 후 첫 설정과 개발용 검토 8건.
- `runtime/verification-20261020T025027Z/report.json`: 검토 분류 지침 보완 후 같은 8건.

## 고정 검토 사례: 개선 전후

`fixtures/review_cases.json`은 의도적으로 구성한 **개발용 사례**다. 프롬프트 수정에 사용했으므로 독립 평가 자료가 아니며 8건 결과를 일반 정확도로 해석하지 않는다.

| 사례 | 기대 | v2 관측 | v3 관측 |
|---|---|---|---|
| C1 가족관계 충돌 | 기준 충돌 | 기준 충돌 | 기준 충돌 |
| C2 능력 조건 위반 | 기준 충돌 | 기준 충돌 | 기준 충돌 |
| C3 정보 획득 시점 | 기준 충돌 | 기준 충돌 | 기준 충돌 |
| C4 사건 연결 누락 | 설명 부족 | 의도 확인 질문 | 설명 부족 |
| C5 명시된 예외 | 지적 없음 | 지적 없음 | 지적 없음 |

분류 일치는 6/8에서 8/8로 바뀌었다. 두 실행 모두 반환된 근거 참조의 존재 검사는 통과했다. v2에서 신규 설정 자체를 질문 사유로 삼는 문제가 있어, 충돌하지 않는 창작적 보충은 허용하고 실제 선택이 필요한 경우에만 질문하도록 지침을 바꿨다. 새로운 사례와 여러 번의 실행에서도 유지되는지는 미검증이다.

## 같은 초안의 수정 전후 관찰

초기 키워드 실행의 D0를 그대로 A로, 검토 후 수정한 D1을 B로 비교했다. D0는 ‘폭풍 경보가 울리면 해 뜨기 전까지 등대에 인계한다’는 규칙을 제시했지만 실제 경보 발생을 명시하지 않았다. D1은 사이렌이 울렸다는 장면을 추가해 규칙 적용 이유를 드러냈다. 코드 작성 에이전트가 두 본문을 직접 대조한 관찰이며 별도의 사람 평가가 완료된 것은 아니다.

| 항목 | A: 최초 생성 | B: 같은 초안+검토·수정·재검토 |
|---|---:|---:|
| 생성 이후 호출 수 | 1 | 4 |
| 입력 토큰 | 1,539 | 13,354 |
| 출력 토큰 | 2,975 | 5,363 |
| 모델 호출 경과 시간(초) | 27.240 | 51.681 |
| 해당 버전의 AI 검토 쟁점 | 설명 부족 1건 | 기록된 쟁점 0건 |

공통 준비 분석은 별도 1회·입력 812/출력 991토큰·5.706초다. B는 A의 생성 비용을 포함한다. 쟁점 감소는 동일 모델의 재검토 관측값이며 정밀도·전체 일관성 보증이 아니다. 문체·설정 변경의 선호 판단과 블라인드 사람 평가는 남아 있다.

## 남은 확인

- LangSmith 키 설정 후 공개 실행의 실제 원격 trace 수신·조회 확인.
- 새 검토 사례를 통한 일반화·오탐·누락 확인과 사람의 창작 품질 평가.
- 개인 5분 발표 시간 측정, 수정 PDF·발표 순서 확인, 공개 범위 검수와 실제 제출.
- 푸시·배포·공개 제출은 수행하지 않았다. API 키·원문·DB·검증 원시 결과는 커밋에서 제외한다.

## 범위와 한계

- 로컬 단일 프로세스·단일 동시 AI 작업. 외부 배포·인증·협업 기능은 제외한다.
- UTF-8 TXT/MD 또는 자유 텍스트. PDF/OCR·Drive 동기화는 제외한다.
- 기준 20,000자, 요청 2,000자. 긴 문서를 조용히 잘라내거나 자동 요약하지 않는다.
- 그래프는 탐색용이며 완전한 설정 목록이나 GraphRAG가 아니다.
- 역할별 모델을 사용해도 창작과 검토의 독립성이 보장되지는 않는다.
- 실제 AI 품질 향상과 LangSmith trace 존재는 각각 실제 실행으로 확인해야 한다.
