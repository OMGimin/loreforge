## 테스트 자료 구성

공개용 키워드와 짧은 가상 설정으로 첫 설정 생성·채택 후 이어쓰기·기존 설정 확장을 검증한다. 특정 작품이나 개인 설정집을 테스트 대상으로 미리 정하지 않는다. 기존 작품은 문제 정의의 참고 자료이며, 기능 검증 자료와 구분한다.

가상 설정의 조건과 의도적으로 넣은 오류는 실행 전에 정리한다. 검토 기능의 시험 사례와 지표는 [평가 계획](EVALUATION.md)에 둔다.

### 2026-10-20 오전 프로젝트 안내 전사

오전 안내 전사 파일 `2026-10-20_091227.txt`를 일정과 발표 준비에 참고했다. 아래 줄 번호는 해당 파일 기준이다. 화자·시각 구분이 없고 인식 오류와 주변 대화가 포함되어 있어 해석에 주의가 필요하다. 원음과 수정 PDF 대조는 남아 있으며, 전사 전문은 저장소에 넣지 않는다.

| 위치 | 확인 내용 | 기획 반영과 해석 한계 |
|---|---|---|
| 10줄 후반 | PDF 일정 오류·수정본 배포, 결과보고까지 1시 마무리 반복 | 10/22 13:00을 준비 기준으로 반영. 앞부분의 모호한 시간 표현보다 후반 정정을 우선하며 수정 PDF 대조 필요 |

계획 등록은 준비되는 대로 할 수 있다는 설명을 기존 17시 마감 폐지로 해석하지 않는다. 제출 전 공개 범위를 점검하고, 업로드 후 저장소·보고서 링크와 제출 상태를 확인한다.

## 기술 자료

- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses): 스키마를 따르는 출력과 JSON 모드의 차이, 거절·불완전 응답 처리 참고. 구조가 맞는다고 내용의 정확성이 보장되는 것은 아니다.
- [Munder Difflin 저장소](https://github.com/HarnessMD/munder-difflin): 기존 실행형 AI를 역할별로 조율하는 방식의 참고 사례. 이 구성을 참고하되, MVP는 보유한 OpenAI API 키로 시작하고 CLI 구독 연동은 후속 과제로 둔다.

API 모델·패키지 버전은 구현 시 실제 가용성과 호환성을 확인하고 고정한다. 이 문서에 모델 최신성·요금·실제 연결 성공을 가정해 적지 않는다.
